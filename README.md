## 安装方法

> **运行环境：**Node.js ≥ 22，DSH ≥ 0.2.1-rc.2。

### 在 DSH 软件中安装（推荐 npm）

1. 打开 DSH **设置 → 插件 → 安装**。
2. 停用旧模板和单独安装的 QQ、记忆、心情、搭话插件，**保留已有数据**。
3. 在安装来源中输入本项目的 **npm 包名**：

```text
dsh-big-flsh-aio@latest
```

4. 确认安装并启用，按提示重载或重启 DSH。
5. 点击左侧栏 **大肥鱼**，配置 QQ 后端、会话绑定，再开启需要的功能。

> **版本说明：**当前项目版本为 `0.3.4`，npm 与 GitHub 仓库使用同一版本号；左侧栏版本号会随项目版本更新。

<details>
<summary><strong>npm 连接较慢？使用国内镜像安装包</strong></summary>

在 DSH 同一个安装来源输入框中，改填以下地址：

```text
https://registry.npmmirror.com/dsh-big-flsh-aio/-/dsh-big-flsh-aio-0.3.4.tgz
```

这是 npm `0.3.4` 的国内镜像安装包，无需访问 GitHub。安装后同样重载或重启 DSH。

</details>

<details>
<summary><strong>需要心情与搭话？使用 GitHub 仓库版</strong></summary>

在 DSH 同一个安装来源输入框中，填写：

```text
github:CHINOSAMAAA/dsh-big-flsh-aio#main
```

此来源包含当前仓库中的全部模块，需要网络可以访问 GitHub。

</details>

**后续更新：**进入 **大肥鱼 → 更新与来源**，npm 版推荐选择 **国内镜像 · npmmirror**，点击 **检查更新 → 一键更新整合包**，完成后按提示重载。仓库版新增功能使用 GitHub 渠道更新。

AIO 与独立插件共用部分接口和数据路径，同一环境只启用一套；切换前先停止正在进行的导入任务。

## 支持功能

| 功能 | 可以做什么 |
| :--- | :--- |
| **统一工作台** | 在 DSH 主内容区查看 QQ、记忆、心情与搭话状态，并进入各模块管理页面。 |
| **QQ 双向互通** | 对接 NapCat / SnowLuma 等 OneBot 后端，配置私聊、群聊、会话绑定、回复策略及图片、文件和语音处理。 |
| **历史聊天导入** | 读取 OneBot 历史、QCE / OneBot JSON 和 QQ TXT，按时间分段整理后写入目标记忆库，支持暂停与恢复。 |
| **图片与 QQ 空间** | 自动转发 DSH 会话生成的图片；发布最多 9 张配图的说说，浏览好友动态、说说与评论，配置定时提醒与自动点赞。 |
| **长期记忆** | 浏览、编辑、整理记忆与档案，配置遗忘和召回；按 QQ 可信来源分库，管理隔离群与授权召回范围。 |
| **Qwen 语义召回** | 按需启用 Embedding，与关键词共同筛选候选；支持索引补齐、续跑和重建，故障时回退关键词。 |
| **鱼的心情** | AI 心情判断、七维情绪、时间线、会话 / 工作区绑定、模型与注入策略，以及可拖拽挂饰。 |
| **主动搭话** | 配置空闲时段、概率、目标会话和冷却，支持演练与手动真发，复用目标会话的人格、工具及记忆。 |
| **更新提醒** | 支持国内镜像和 GitHub 更新；后台检测 npm 新包，使用 DSH 原生 Toast 提醒，旧宿主显示兼容提示条。 |

**表情包：**在「QQ 互通 → 表情包」中管理素材，按需开启语境发送、自动收藏、视觉标签与自动分类。空间评论仍仅向模型递送动态，本模块没有发表评论的工具。

**使用提示：**历史整理、心情判断与真实搭话会调用配置的模型；启用语义召回后，正文和查询会发送到配置的服务商，并可能产生费用。QQ 默认关闭转发并开启试运行，Embedding 默认关闭，搭话默认试运行，可按需逐项启用。


## 图片与文件及语音转写

「QQ 互通 → 图片与文件」仅配置绑定 DSH 会话生成图片的自动转发，支持会话回复的图片附件与 Markdown 图片，每轮最多 4 张，遵守消息开关、大小上限与试运行。生成图片转发不提供手动发送或上传；旧 `/dsh-qq-bridge/send-images` 接口保留鉴权但明确拒绝发送。转发只读取既有生成图片；QQ 接收内容可通过各自的存储开关另存归档。

「语音转写」独立为排在「表情包」之后的子页，保留转写开关、识别环境安装、命令生成、模型目录与参数。「图片与文件」内分区管理 QQ 图片接收、DSH 生成图片转发、QQ 文件接收与 DSH 生成文件转发；原收发配置保持兼容，表情包库和 QQ 空间配图使用各自入口。

### 启动大肥鱼

总开关初始默认关闭。开启「QQ 互通 → 连接 → 大肥鱼，启动！」时，后台检查试运行是否关闭、QQ 后端连接与账号在线状态、每条启用映射的历史消息读取、独立会话绑定、会话是否已打开或归档，以及模型和服务商配置。至少需要一条启用的映射；全部群聊回复路径被概率设置关闭时也会提示调整。检查不发送测试消息、不调用模型生成内容、不保存设置。

未通过时开关保持关闭，通过 DSH 原生提示汇总具体页面和待操作项，其他草稿保留。检查通过后允许打开开关，再点击「保存设置」；后台在保存从关闭到开启的状态时重新检查，防止直接请求绕过。检测期间修改配置、取消开启或后续关闭保存会使旧结果失效。关闭开关不执行启动检查；记忆、心情、主动搭话、图片、文件及工作区存储不是纯文字启动的必开项目。

### 大肥鱼的工作区

在「QQ 互通 → 连接 → 大肥鱼，启动！」的总开关下方选择「绑定工作区」，然后保存设置。下拉框读取 DSH 全部登记的工作区，显示名称和路径；按工作区 ID 保存，同名工作区也可区分。目录不要求叫 BigFish，首次使用需明确选择；失效目录不能继续写入。

QQ 图片、文件和新表情原图分别写入所选工作区的「QQ图片」「QQ文件」「表情包」目录。切换不自动移动或删除已有归档；回选原工作区即可管理其归档。表情库原有素材仍可从其已登记工作区读取。插件配置、记忆及会话日志继续由 DSH 原有机制管理。

### 图片与文件存储管理

- 在 QQ 图片接收区和 QQ 文件接收区分别开启「开启图片存储」「开启文件存储」，两个开关均默认关闭，保存设置后生效。关闭后停止新增归档，不删除已有内容，接收并提交 DSH 附件的流程继续工作。
- 新接收的原图与文件分别归档到 所选工作区的 `QQ图片`、`QQ文件`，首次启用并接收内容时自动创建。存储路径自动定位，不在插件中写入机器路径。按内容和聊天来源去重，避免文件同名覆盖；写入途中关闭、取消或超限时清理未完成文件。
- 「文件管理」页签中各自的「管理已存图片 / 文件」弹窗显示名称、大小、来源和时间，支持图片预览、原文件下载及删除确认。关闭存储后仍能管理已有归档；删除仅作用于归档副本，不删除 DSH 会话中的附件。
- 这两个开关控制额外归档，DSH 处理消息所需的附件缓存仍由宿主管理。表情包素材库使用自己的目录和开关；旧 `qq-bridge-inbox` 原图与历史附件保持原样，不自动迁移或清空。
- 归档失败不阻断消息接收。文件归档需宿主提供 `readFileStream`；缺失能力时文件仍交给 DSH，并明确提示额外存储失败。

### QQ 文件接收

- 默认关闭，启用后将绑定私聊 / 群聊中 `file` 消息段的文件作为 DSH 通用附件提交，沿用现有群聊接收 / 点名规则和消息去重；不自动执行文件。
- 默认每次最多 3 个、单文件最多 20 MB；数量可设 1～10，单文件可设 1～100 MB。连续消息合并后共用数量上限；声明大小、HTTP 长度和下载实际字节数均会检查，超限跳过，单个失败不影响其余文件与文字。
- 自动适配 NapCat / SnowLuma：保留群文件 `busid`、私聊 `file_hash` 与原始文件 ID。优先直链 / Base64，后备使用 `download_file_stream`，通过已配置的后端获取字节；后端仅返回 Docker 容器路径时按文件 ID 请求文件流，不读取宿主同名路径、不要求共享目录。
- 直链仅接受 QQ 文件域名、已配置的 OneBot 服务，以及经过已认证后端解析的公共 IPv4 CDN 地址；拒绝消息指定的本地路径和其他内网地址，重定向重新校验。直链请求的管理令牌仅发给已配置后端。文件由 DSH 附件服务保存、管理和去重，具体文件格式的处理能力取决于宿主、模型和工具，可能产生模型用量。
- 除历史 `file` 消息段外，自动监听文件消息、群文件上传与私聊离线文件通知；复用现有 HTTP 连接配置尝试 SSE / WebSocket。同一文件的事件通知和历史记录共用去重与投递流程，迟到事件不会被普通消息的时间水位吞掉；仍遵守群聊点名、频率与绑定规则。
- 本机 Docker 部署会只读查找发布了现有 HTTP 端口且口令匹配的容器，读取对应账号的 OneBot 监听配置并使用已发布的 WebSocket 端口与口令，不修改 Docker 配置、不重启容器、不新增地址 / API 设置。配置位置覆盖 SnowLuma `/app/data/config`、NapCat `/app/napcat/config`；远程独立 WS 使用不同口令、未发布事件端口、非标准路径或宿主无法访问 Docker 时，无法自动获知私有配置，设置页会显示事件通道未连接，历史接收仍可用。
- 需要支持 `saveFileStream` 的 DSH 文件附件服务；文件流校验分块序号、实际大小与完成确认，超限、取消或不完整下载不会提交附件。缺少能力或接收失败会在转入消息与日志中说明。

## 自动表情包

- **素材处理会话**：先在 DSH 中新建并打开独立会话，选择现有 DeepSeek 模型，再在「QQ 互通 → 表情包 → 自动发送冷却」下方填入会话 ID，离开输入框自动保存。专用会话仅承接手动导入、批量导入、扫描补标签与单张重试；每张图片独立请求，不追加会话聊天记录，不需要额外视觉服务商配置。不要将它绑定 QQ、记忆或主动搭话。会话未打开或没有模型时会明确报错。
- **单张导入**：位于「打开表情包素材库」按钮下方，可选择来源范围，在同一个标签输入框选择已有标签或输入新标签，多个标签用逗号分隔；留空时自动生成。移除名称和使用场景输入，DeepSeek 识别后按“首个标签-图片描述”命名，名称最多 23 个字符，同时补齐场景与分类。人工标签保持不变。
- **批量导入**：点击唯一的批量导入按钮多选原图，逐张入库后排队处理，标签、名称、场景与分类均自动生成，默认共享素材。单张失败不阻断其余图片，界面报告成功数与具体失败原因；识别失败会保留原图，可在素材库预览中重试。手动导入和扫描不依赖自动标注 / 分类开关。
- **素材存放**：PNG / JPEG / GIF / WebP 原图保存在 DSH 登记的 `BigFish/表情包` 文件夹（也识别 BIGBISH 路径名），每张最多 8 MB、全库最多 500 张 / 256 MB。通过工作区登记定位，不将机器绝对路径写入插件。配置、标签和索引继续保存在 DSH 数据目录 `qq-stickers/catalog.json`；旧原图首次访问时复制迁移并保留原目录备份，同名内容冲突时停止操作，不覆盖原文件。删除素材会删除新旧目录中的对应原图。
- **素材库**：按实际标签与“未分类”筛选、搜索缩略图，点击原图预览和编辑。扫描全部素材仅为无标签的图片排队，已有标签即使缺少场景也跳过。弹窗标题与关闭按钮固定，内容独立滚动，滚动条上下端留在圆角以内。
- **语境自动发送**：继续使用目标 QQ 会话的模型，综合最近 QQ 消息、助手回复及候选素材选图；不合适、模型失败、已有配图或冷却期间不追加，遵守 QQ 开关、试运行、独占绑定与发送图片开关。
- **自动收藏与标注**：收藏启用绑定中的实时大表情、表情图片与 GIF，不需要点名；普通图片需额外开启，不回扫历史。自动收藏的图片仍使用所属绑定会话进行自动标注，共享素材可复用启用绑定。自动分类支持 12 个内置类别，保留手动分类；这些自动化开关默认关闭，不影响主动导入流程。

图片会发送给所用会话的模型服务商并产生用量，GIF 按可解码画面识别，收藏和发送保留原文件。共享素材可由所有绑定使用，指定来源及自动收藏素材按来源隔离。实际 QQ / DeepSeek 兼容性仍需真实环境验证，自动测试使用模拟后端与模型。
